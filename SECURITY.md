# Security policy

## Reporting a vulnerability

Never disclose a suspected vulnerability in a public issue, pull request,
discussion, commit message, or other public channel.

The intended reporting channel is GitHub private vulnerability reporting. This
file does **not** enable that repository setting. Before public launch,
maintainers must enable it and verify that the repository's **Report a
vulnerability** action is available.

When that action is available, open the repository's **Security** tab, select
**Advisories**, and choose **Report a vulnerability** to submit the details
privately. Follow GitHub's
[private vulnerability reporting documentation](https://docs.github.com/en/code-security/security-advisories/working-with-repository-security-advisories/configuring-private-vulnerability-reporting-for-a-repository)
for the setting's behavior.

If **Report a vulnerability** is unavailable, do not send vulnerability details
publicly. Contact the repository owner through GitHub without sensitive details
and ask for a private reporting channel.

Do not use the Code of Conduct enforcement email as a security fallback.

## Supported versions and response expectations

There are no published releases and no supported-version or backport matrix yet.
The project makes no response-time, fix-time, disclosure-date, CVE-assignment,
support, or SLA promise. Any future supported release would require a separately
documented version policy.
